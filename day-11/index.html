02
The breakdown · the Polaroid version

Six ideas, that's all

What it is, the dev version, and the trap

A Polaroid starts as a murky square and the picture slowly appears. A diffusion model does something that looks the same, but underneath, a trained model is removing noise one small guess at a time.

  • NoiseTV static

    Random speckle added on top of a picture: every pixel nudged lighter or darker by a random amount. A little noise makes a photo grainy. A lot of it, and there's no photo left, just static.

    Dev: Random numbers from a bell curve, added to every pixel

    Watch out: The noise isn't hiding the picture somewhere. Pure static has no photo inside it. The picture gets invented as the noise comes out.

    Adding noise, in one line
    noise = random_normal(image.shape) noisy = image + amount * noise # amount = 0: clear photo # amount large: only static

  • Trainingruin photos on purpose

    Take millions of real photos. To each one, add some noise: sometimes a little, sometimes so much it's pure static. Now you have endless practice questions, and you already know every answer, because you added the noise yourself.

    Dev: Self-made labels. No human tags a single example

    Watch out: The reel shows noise piling up "then more, then more". In real training each photo gets one random noise level at a time, picked from about 1,000 possible levels. Same idea, shuffled order.

    One training example
    photo = random_photo() level = random_int(1, 1000) noise = random_normal(photo.shape) noisy = add_noise(photo, noise, level) # question: noisy, level # answer: noise

  • The noise guesserthe actual model

    The model is shown a noisy photo and asked one thing: what noise was added? Every wrong guess nudges its settings a little. After millions of photos, it gets very good at spotting what's static and what's picture.

    Dev: A neural network trained to predict noise; loss = how far off the guess was

    Watch out: It doesn't output a picture. It outputs its guess of the noise. The picture is whatever is left when you take that guess away.

    How the guess is scored
    guess = model(noisy, level) loss = mean((guess - noise) ** 2) # small loss: it found the static # then: nudge the weights, repeat

  • Generationstart from pure static

    To make a brand-new picture there's no photo at all. You start with pure random static, ask the model what noise it sees, take away a little of it, and ask again. Each pass, the static gets a bit more picture-like.

    Dev: A loop. Same model, called again on its own output

    Watch out: It removes only a slice of the guessed noise each step, not all of it. One big jump gives a blurry mess; many small steps give detail.

    The whole generator
    x = random_normal(shape) # static for level in steps: # high to low guess = model(x, level, prompt) x = remove_some(x, guess, level) picture = x

  • The promptsteers every step

    Your sentence is turned into numbers and handed to the model on every single step. So each guess is really "what noise is here, if this is meant to be a sun over green hills?" That pulls the static toward what you typed instead of any random picture.

    Dev: The prompt is an extra input to every model call, not a one-off setting

    Watch out: Stable Diffusion runs each step twice, once with your prompt and once without, and push further in the direction of the difference. How hard they push is the "guidance scale". Too high and pictures start to look overcooked.

    Guidance, roughly
    with_p = model(x, level, prompt) without_p = model(x, level, "") guess = without_p + scale * (with_p - without_p) # scale around 7 is a common default

  • Stepsabout 25

    How many clean-up passes you run. More steps means more detail but a slower picture. The classic Stable Diffusion code defaults to 50; faster step methods get high-quality pictures in about 20. That's why the reel says "about 25".

    Dev: The loop count: num_inference_steps

    Watch out: It's a speed-versus-quality dial, not a fixed number. Tools like Leonardo.ai pick it for you and don't show it.

    Same model, different budgets
    steps = 50 # Stable Diffusion default steps = 20 # fast method, still sharp steps = 10 # "quite good" with that method steps = 1 # a blurry guess
In one line It's not painting. It's un-noising, guided by what you typed. The code boxes are simplified pseudocode, so you can see the shape of each idea. They won't run as written.

04
Try it in code · optional

Pick your own step count

For when you want the dials Leonardo hides

Hugging Face's diffusers library runs Stable Diffusion in a few lines. This is adapted from their docs. It downloads the model the first time (a big file) and wants a GPU (an Apple-silicon Mac works with "mps"). Change the two numbers and compare.

# pip install diffusers transformers accelerate torch
from diffusers import AutoPipelineForText2Image
import torch

pipe = AutoPipelineForText2Image.from_pretrained(
    "stable-diffusion-v1-5/stable-diffusion-v1-5",
    torch_dtype=torch.float16,
).to("cuda")   # or "mps" on a Mac

image = pipe(
    "a sun over green hills, polaroid photo",
    num_inference_steps=25,   # the loop count
    guidance_scale=7.5,       # how hard the prompt steers
).images[0]
image.save("day11.png")

05
What 40 seconds left out

The honest footnotes

True, just too much for a reel

  • It works on a tiny versionStable Diffusion doesn't clean up the full-size picture. It works on a small compressed summary of it, then a decoder blows that up into the final image. Much cheaper, almost no loss.
  • Noise levels get shuffledTraining doesn't walk one photo from clear to static. Each example gets a random noise level, so the model practises every stage of the clean-up.
  • Two pictures, same promptDifferent starting static, different picture. Tools let you fix the starting static with a "seed" number when you want the same result twice.
06
Self-check

Say these out loud

If you can answer all five, you've got it

  1. Where do the training labels come from, if nobody tags anything?
  2. The model's output each step is a guess of what?
  3. Why remove only a little noise per step instead of all of it at once?
  4. Where does your prompt come in: once at the start, or every step?
  5. Same prompt, run twice, different picture. Why?
