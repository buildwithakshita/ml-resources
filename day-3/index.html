Notationm = number of examplesn = number of featuresx(i) = the i-th exampleŷ = predictionα = learning rate

  • Featuresinputs

    The columns the model learns from. One example is a row of features; the whole dataset is a table of m rows and n features.

    Dev: Function arguments

    Watch out: More features isn't automatically better. Irrelevant ones add noise.

    Notation
    x = (x1, x2, …, xn)  ·  X has shape (m, n)
    X = df[["hours_slept", "lines_of_code"]]

  • Targetoutput

    The answer you want the model to predict. The model's guess is written ŷ ("y-hat"); the real answer is y.

    Dev: Expected output in a unit test

    Watch out: Never let the target sneak into the features ("data leakage"). Your model will look perfect and fail in prod.

    Notation
    y = real answer  ·  ŷ = prediction
    y = df["bugs_shipped"]

  • Linear regressionpredicts a number

    Multiply each feature by a weight, add them up, add a bias. Training means finding the w and b that fit the data best.

    Dev: A function with tunable config values

    Watch out: It assumes a roughly straight-line relationship. Curvy data needs extra features (e.g. x²).

    Model
    fw,b(x) = w · x + b = w1x1 + … + wnxn + b
    LinearRegression().fit(X, y)

  • Logistic regressionpredicts yes / no

    Same linear formula, then squashed by the sigmoid into a probability between 0 and 1. Above 0.5 means "yes".

    Dev: Same function, plus an if-statement

    Watch out: Despite the name, it's a classification model, not regression.

    Model
    z = w · x + b  →  g(z) = 11 + e−z
    predict 1 if g(z) ≥ 0.5, else 0

  • Cost functionhow wrong

    One number that sums up how wrong the model is across every example. Errors are squared so big misses count much more than small ones.

    Dev: Your failing test count

    Watch out: Linear and logistic use different costs. Squared error makes logistic's cost bumpy, so it uses log loss.

    Linear: squared error
    J(w,b) = 12m Σi=1m (f(x(i)) − y(i))2
    Logistic: log loss
    L = −[ y log(ŷ) + (1 − y) log(1 − ŷ) ]

  • Gradient descenthow it learns

    Repeat: work out which direction lowers the cost (the gradient), take a small step that way. Stop when the cost stops dropping.

    Dev: A for loop: nudge, rerun, repeat

    Watch out: Update w and b at the same time, using the old values for both.

    Repeat until converged
    w := w − α ∂J∂w    b := b − α ∂J∂b
    ∂J∂w = 1m Σ (f(x(i)) − y(i)) x(i)    ∂J∂b = 1m Σ (f(x(i)) − y(i))

  • Learning ratestep size

    α controls how big each step is. Too big and the cost bounces or explodes; too small and training crawls.

    Dev: Step size per iteration

    Watch out: Plot cost vs iterations. It should go down every time. If it goes up, α is too big.

    Values to try (≈3× apart)
    α ∈ { 0.001, 0.003, 0.01, 0.03, 0.1, 0.3 }
    cost rising → α too big cost flat-ish → α too small

  • Feature scalingsame range

    Rescale features so they cover similar ranges. Otherwise one large-valued feature dominates and gradient descent zigzags slowly.

    Dev: Converting ms and seconds to one unit

    Watch out: Fit the scaler on training data only, then apply the same μ and σ to test data.

    Standardisation (z-score)
    x′ = x − μσ    mean 0, most values in −3…3
    Min-max
    x′ = x − minmax − min    range 0…1

  • SGDfast updates

    Stochastic gradient descent updates after one random example (or a mini-batch of 32–256) instead of the whole dataset. Each step is noisier, but far faster.

    Dev: Run one test, fix, repeat

    Watch out: A jumpy cost curve is normal. Shuffle the data every epoch (one full pass).

    Update per example i
    w := w − α (f(x(i)) − y(i)) x(i)
    SGDRegressor().fit(X_scaled, y)
Gradient descent from scratch linear regression · NumPy · 12 lines
# X: (m, n) scaled features, y: (m,) targets import numpy as np def train(X, y, alpha=0.01, iters=1000): m, n = X.shape w, b = np.zeros(n), 0.0 for _ in range(iters): err = X @ w + b - y # f(x) - y for every example w -= alpha * (X.T @ err) / m # dJ/dw b -= alpha * err.mean() # dJ/db cost = (err ** 2).mean() / 2 return w, b, cost
