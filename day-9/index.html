02
The cheat sheet

Six ideas, that's all

What it is, the dev version, and the trap

Every chatbot you've used, from ChatGPT to Claude, runs on this loop.

  • LLMlarge language model

    A huge neural network trained on a lot of text to do one job: given some text, predict the next token.

    Dev: A function that takes a string and returns odds for what comes next

    Watch out: It doesn't look things up by default. It predicts what's likely.

    The job
    text → next token

  • Tokena word or a piece of one

    Text gets chopped into chunks from a fixed vocabulary, and every chunk becomes a number. Common words are one token; rare words get split into pieces.

    Dev: Like an enum: every chunk of text has an ID

    Watch out: Models count, price and limit everything in tokens, not words.

    Example (made-up IDs)
    "where's the Eiffel Tower?" → [where][’s][ the][ Eiff][el][ Tower][?] → [1734, 596, 279, 88430, 301, 22703, 30]

  • Chat templatethe hidden text

    Your message is wrapped in hidden text before the model sees it: a system prompt, "User:", your message, then "Assistant:". The answer is just the most likely text after "Assistant:".

    Dev: A request wrapped in headers you never see

    Watch out: "Memory" is just extra text added into this prompt behind the scenes.

    What the model sees
    [system] You are a helpful assistant. User: where's the Eiffel Tower? Assistant: ▍

  • Logits & softmaxscores → odds

    The model gives every token in its vocabulary a raw score (a logit). Softmax turns those scores into probabilities that add up to 100%.

    Dev: Normalising a list of scores into percentages

    Watch out: Even "pizza" gets a tiny chance. Nothing is ever exactly 0%.

    Softmax
    pi = eziΣj ezj
    p = exp(z) / exp(z).sum()

  • Sampling & temperaturerolling weighted dice

    The model picks the next token at random, weighted by those odds. Temperature controls how random: low = almost always the top token, high = more surprising picks.

    Dev: random.choices(tokens, weights=probs)

    Watch out: This is why the same question can give you different answers.

    With temperature T
    pi = ezi/TΣj ezj/T
    p = exp(z / T) / exp(z / T).sum()

  • The loopone token at a time

    Pick a token, stick it on the end, and run the whole model again. Repeat until it picks a "stop" token. Every answer you've ever seen was built this way.

    Dev: A while loop that appends to a string

    Watch out: The prompt shifts every step's odds. Add "I'm in Vegas" and "the Strip" beats "Paris".

    Generation
    while token != STOP: probs = model(text) token = sample(probs) text += token
Bonus Why not always pick the top token? You can (that's temperature near 0). But answers get repetitive and flat, so a little randomness makes them sound more natural.
03
Try it in 10 lines

Roll the dice yourself

The Eiffel Tower example from the reel, in Python

Made-up scores for three tokens. Run it a few times, then change T to 0.2 and 2.0 and see what happens.

# the first word of the answer to "where's the Eiffel Tower?"
import numpy as np
tokens = ["The", "It's", "Paris"]
logits = np.array([8.1, 7.4, 5.2])   # example scores

def sample(logits, T=1.0):
    p = np.exp(logits / T)
    p = p / p.sum()                  # softmax → adds up to 1
    return np.random.choice(tokens, p=p), p.round(3)

print(sample(logits, T=1.0))   # usually "The", sometimes "It's"
print(sample(logits, T=0.2))   # almost always "The"
print(sample(logits, T=2.0))   # much more random
